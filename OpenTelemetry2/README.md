-> Day 1

- What is Observability
  - Observability = Understanding a system's tate using logs, metrics, and traces. It helps answer "Why is this happening?" .Without knowing internal code.

- **How Observability Helps**
  - _Telemetry Data_
    - Logs : Records event happening inside the app
    - Metrics : Shows numerical performance values (latency, request rate, error rate).
    - Traces : Shows the full journey of a request across microservices.

- Observability Concepts
  - The following are the three key verticals of observability.
    - Metrics
    - Logs
    - Traces

- **Logs**
  - _What Are Logs?_
    - Records of events happening inside an application.
    - Contain timestamp, severity, message, and optional context (user Id, session Id, Request details).
    - Generated by developers using loggins libraries
  - _Example Log Entries_
    - INFO : Starting getUserById for userId=12345
    - DEBUG : Fetching user data from database
    - INFO : User data retrieved.
    - WARN : Outdated profile information
    - ERROR : Failed to send notification email
  - _Types of Logs_
    - Plain text logs
    - Structured logs (JSON, XML)
    - Binary Logs (protobuf, MySQL Binary logs, Systemd Journals)
    - Custom formats

- **Metrics**
  - _What Are Metrics_
    - Numerical data measured over intervals of time.
    - Help detect trends, patterns, and system behavior
  - _Example_
    - http_requests_total{method="post",code="200"} 1027
  - _Why Metrics matter_
    - Quick snapshot of system health
    - Help identify performance issues
    - used for monitoring dashboards and alerts

- **Traces & Spans**
  - _What is Distributed Tracing ?_
    - Tracks how a request flows through multiple microservices.
    - Helps understand latency, bottlenecks, and request behavior
    - _Trace_ : Represents the entire journey of a request (Ex: Placing an order)
    - _Span_ : Represents a single step in that journey (Ex: DB query, service call)
  - _Example Scenario_ User places an order -> Request passes through:
    - Order service
    - inventory service
    - payment service
    - user account service
  - _Benefits_
    - Identify slow microservices
    - Detect where latency increases
    - faster debugging of distributed systems
